## Rig 2.1.0

A reliability release: safer file operations, an honest Similar Photos, Game Mode that always puts things back,
backups that respect privacy, and a lighter app in the background.

### Safer file changes
- **Batch Rename and Downloads keep a recovery record** for every batch, written before the first file moves.
  Files are checked again just before they move, names can swap, and nothing is ever overwritten.
- **Undo never loses a file.** If a new file has taken an old name since, both files are kept and the batch is listed
  in the new **File recovery** window (Try again, Keep both files, or Leave as is). Batches cut short by a crash are
  picked up on the next start.
- Clear results: renamed, skipped, in the way, or failed, with details.

### Similar Photos
- **Exact copies** (byte-for-byte) and **look-alikes** are now separate. Only exact copies are ticked for the Recycle
  Bin; look-alikes are suggestions you check yourself.
- Each group explains why it matched and suggests a keeper you can change ("Keep this"). Plain pictures (flat colours,
  near-empty frames) are never matched by look. Photos that can't be read are listed instead of silently skipped.

### Game Mode
- Every change (power plan, game priority, resolution) is written down before it's made and only crossed off once it's
  been put back, so a crash, a power cut or a failed restore is finished on the next start. The game page shows what
  was applied, skipped or still to restore, with **Try restoring again**.
- It puts back your original values (the priority the game had, the resolution you had), and leaves things alone if
  you changed them yourself meanwhile.
- Apps are now asked to close and left open if they don't respond (they might have unsaved work). Force-closing is
  a separate, clearly labelled option.
- Uninstalling or updating asks the running Rig to quit properly, so Game Mode and recordings finish first.

### Settings and backups
- Importing a setup shows a preview where you choose preferences, personal data, tweaks and app suggestions
  separately. Your current setup is saved first. A shared setup can't switch on clipboard history, screen time or
  input counting unless you say so. Timers and reminders are part of a full backup.
- Settings are saved atomically with a last-good copy; a damaged file is kept and the last good copy is used. Rig
  tells you if settings couldn't be saved.

### Updates and recordings
- Updates are checked against GitHub's published checksum, and the previous version is kept until the new one starts
  properly; if it fails to start three times, the previous version comes back. Signed updates are supported once a
  signing key is set up (see docs/SIGNING.md; this release isn't signed yet).
- Closing Rig, restarting or updating now waits for a screen recording to finish, so the file is always playable.

### Everyday
- Settings has new **Privacy & data** and **Keyboard shortcuts** sections.
- Home: the health card is now a **Maintenance check** that says what it's based on and when it ran; a compact layout
  preset; one column on narrow windows; media buttons are disabled when nothing is playing.
- The first-run welcome explains the tray, automatic changes, clipboard history and screen time, and asks about the
  tracking features instead of turning them on. The portable option now says what it still saves.
- Accessibility: every switch can be reached with the keyboard, has a visible focus outline and a name screen readers
  can say; form fields have visible labels; status lines are announced; animations follow Windows' setting; Windows'
  contrast themes are supported.
- Background: Home's charts and the now-playing check pause while not on screen. The command palette finds settings
  without building every page (first open about twice as fast; see docs/PERFORMANCE.md).
